# Phase 3 사전 고정 — 개발 통합 재현과 동결 준비

이 문서를 먼저 커밋한 뒤 P3 전체 개발 CV/재봉인/부분 재현/dry-run을 실행한다. 커밋 후 수정하지 않는다. P2 후보·선정 규칙과 결과를 보고 새 후보를 추가하지 않는다.

## 입력과 최종 후보 집합

- 개발 prefix만 사용: 목표값 < 2021-08-09 09:45. 전체 원자료 파싱, 실제 final 단계 호출, final_test.csv 생성 금지.
- 기존 후보 집합에 P2 고정11구성(M1 h4/h16/h96, M4 4종×h16/h96)을 그대로 추가하고 같은3폴드로 실행한다. h4 M1은 참고 전용, M2/M3·새 격자·새 특징은 없다.
- 예상 선정은 h1 p1_latest, h4 lgbm_no_holiday_weight_2, h16 lgbm_residual_cbl, h96 c3_holiday_hybrid, 위험 출력은 전부 기존 conformal B다. 이는 P2를 재현할 예상값이며 결과가 다르면 임의로 고정하지 않고 차이 원인을 기록한다.
- 원본 OOF/선정은 `_validation/session_0925_original/`, P2 신규 후보 OOF/표는 `_validation/session_0925_P2/`에 보존했다. 개발 데이터 캐시를 사용하지 않고 안전 prefix와 고정 코드로 재생성한다.

## 실행과 통과 기준

1. `python run_all.py --development-only --rebuild-dev`를 한 번 실행한다. 기존 T1 모든 예측거리와 T2, 등록 연구 후보를 포함한다. 전체30분 목표, 30분 초과 예상 시 무조건 반복하지 않고 완료 상태를 보존하고 영향받은 거리만 재현한다. 실패 시 모델·기준 변경 없이 원인을 기록하고 버그 수정 범위에 한해 재실행한다.
2. 원후보의 모든 대응 OOF 행을 원본과 비교한다. 특히 선정이 바뀌지 않은 h1/h4/h96은 원점·목표·fold·model key, y/tau/예측·분위수·확률·경보가 같아야 한다. 수치 허용오차는 절대1e-10(rtol=0), NaN 위치 동일, bool/범주/시점은 정확히 동일. h16 원후보도 같은 기준으로 확인한다.
3. 신규 후보의 P3 OOF와 독립 P2 OOF도 같은 key와1e-10 허용오차로 비교한다. 선정 전후·후보 탈락 이유가 동일해야 한다. 같은 설정의 재학습은 신규 후보로 세지 않고 실제 fit 횟수만 누적한다.
4. 캐시 없는 부분 재현: h16 fold2 잔차1개와 h96 fold2 원 분위수5개를 다시 적합하고 고정4개 온라인 보정을 재생한다. P3 해당 OOF와1e-10 비교, 미래 관측 가용 시점과 원 calibration 경계를 확인한다. 추가 모델/후보 선택에는 사용하지 않는다.
5. P1의 사전 정의 근접성·오류 분해와 운영 재평가의 주요 통계를 개발 prefix에서 캐시 없이 부분 재계산해1e-10 이내를 확인한다. P1 빈 AUC 코호트는 빈 상태 자체를 확인한다. 결과에 맞춰 코호트를 바꾸지 않는다.
6. 현재 코드·기본 설정·원자료 불투명 해시·선정·prereg·특징 게이트·모델 번들로 개발 캐시를 봉인한다. `python run_all.py --dry-run-freeze`는 이 검증만 통과하고 어떤 데이터 loader/최종 평가 함수도 호출하지 않아야 한다. 날짜 잠금과 사람 승인 미완료는 준비 실패가 아니라 예정된 별도 게이트로 보고한다.
7. 전체 `python -m pytest -q` 통과, preflight의 보호75파일 해시 동일, 사전등록3문서 커밋 후 불변, 실제 최종 산출물 없음, 자동 동결 작업 Disabled 유지가 완료 기준이다. 테스트 수·직접 exit code·소요시간·재현 최대오차를 기록한다.
