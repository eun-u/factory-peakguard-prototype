# 전력 피크 판단 흐름 · 실행형 프로토타입

제공된 `okm_augumented_2021.csv`로 과거 전력 → 15·30·60분 예측 → 임시 피크 위험 → 불확실성 → 운영 판정을 한 화면에서 살펴봅니다. 대회 제출용 성능 또는 실제 설비 제어 시스템이 아닙니다.

## 실행

Python 3.13 기준, PowerShell에서 저장소 루트로 이동한 뒤:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run prototype/app.py --server.address 127.0.0.1
```

표시되는 로컬 주소(보통 `http://localhost:8501`)를 엽니다. 앱은 저장소의 `data/raw/task05_power/source.zip`을 읽습니다. ZIP은 수정하지 않았으며 SHA-256은 `02640b4cc90967c26a897953e43f42be0c9b0ca971364fa20b587cb50466b63a`입니다. 다른 위치에서 실행할 때도 저장소 내부의 이 상대 경로를 유지하세요.

## 화면에서 볼 것

1. 상단에서 **과거 날짜·시간**을 고르면 그 시점까지만 알고 있었다고 가정합니다. 모델 학습, 피크 임계값, 검증 잔차도 매번 그 시점 이전 자료만으로 계산합니다.
2. **예측 방법**을 바꾸면 현재값 유지, 지난주 같은 시각, 간단한 트리 모델을 같은 기준으로 비교할 수 있습니다. 마지막 펼침 영역에 시간순 검증 MAE가 나옵니다.
3. 중앙 그래프의 주황 선은 15·30·60분 전력 예측, 옅은 띠는 검증 오차로 만든 경험적 예측 범위입니다. 빨간 점선은 학습 전력의 상위 5% 임시 피크 기준입니다.
4. 하단에서 시점별 피크 위험과 범위가 임계선에 겹치는지를 봅니다. 마지막 상태는 단순 규칙의 결과입니다.

실제 데이터에서 상태를 둘러볼 예시 시각(기본 트리 모델): `2021-09-15 00:00`은 `NORMAL`, `2021-09-14 08:30`은 `PEAK_WATCH`, `2021-08-24 08:30`은 `LOAD_SHIFT_REVIEW`, `2021-07-13 23:45`는 시각 복원 때문에 `REVIEW_REQUIRED`입니다. 이 예시는 현재 코드와 데이터에서 재현한 값이며 임시 규칙의 동작을 보여줍니다.

## 데이터와 계산 규칙

- 원본은 6,168행 × 18열입니다. 날짜·시간 및 `15분`, `30분`, `45분`, `60분`만 입력에 사용하고 24,672개 15분 관측으로 전개합니다. `15분`은 HH:15, `60분`은 다음 시각 HH:00으로 **가정**했습니다. 원자료의 측정 단위(kW/kWh)와 구간 경계 의미는 미확인입니다.
- 2021-07-13과 2021-07-15의 시간 열 48행이 0~23 범위를 벗어납니다. 각 날짜가 24행이고 다른 날짜는 0~23 순서임을 확인한 뒤, 해당 날짜만 원본 행 순서로 시각을 **잠정 복원**합니다. 복원 구간의 최근 관측을 선택하면 `REVIEW_REQUIRED`입니다. 원본 ZIP은 그대로 보존됩니다.
- 전력값의 결측·음수는 탐색용 시계열에서 결측으로 취급합니다. 최근 1시간에 결측이 있으면 `REVIEW_REQUIRED`입니다. 실제 CSV의 전력 4개 열에는 결측이 없습니다. 풍속 3건, 강수량 1건, 공장인원 17건의 결측은 해당 열을 예측 입력으로 사용하지 않아 채우지 않습니다.
- 모델 입력은 선택 시각까지의 전력 시차, 최근 평균, 예측 대상 시각의 달력 정보뿐입니다. 미래 생산량·기상 실측, 시간별 평균 전력은 사용하지 않습니다. `지난주 같은 시각`은 **예측 대상 시각보다 7일 앞선 관측**을 사용하며, 없으면 현재값으로 대체하고 검토 상태로 표시합니다.
- 각 선택 시점의 과거 자료를 시간순으로 대략 앞 80% 학습·뒤 20% 검증으로 나눕니다. 예측 목표가 학습 끝을 넘는 행은 학습에서 제외합니다. 피크 임계값은 학습 구간의 정상 시각 전력값 95% 분위수입니다. 검증 잔차의 절댓값 90% 분위수를 각 예측값 양옆에 더합니다. 이것은 설명용 경험적 범위이며 미래 90% 적중을 보장하지 않습니다.
- 피크 위험은 각 예측값이 임계값 이상인지의 **이진 표시**입니다. 구간이 임계선과 겹치는지도 따로 표시합니다. 전체 구간 폭이 임계값의 30% 이상이거나 최근 입력 품질 문제가 있으면 `REVIEW_REQUIRED`; 그 외 현재·예측 전력 중 하나가 임계값의 105% 이상이면 `LOAD_SHIFT_REVIEW`; 임계값 이상이면 `PEAK_WATCH`; 나머지는 `NORMAL`입니다. 이 수치는 모두 프로토타입용 규칙입니다.
- `LOAD_SHIFT_REVIEW`는 이동 가능한 작업이나 동시가동 부하를 **운영자가 검토**하라는 뜻입니다. 특정 설비 조작, 최적 스케줄, 절감액, 자동 제어는 만들지 않습니다.

## 확인

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s prototype/tests -v
```

앱 실행 후 최신 시점과 임의의 과거 시점을 선택해 그래프·세 예측값·판정이 갱신되는지 확인할 수 있습니다.
